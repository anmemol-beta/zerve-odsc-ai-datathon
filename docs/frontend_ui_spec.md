# Presentation Frontend · UI Composition Spec

> 3분 영상과 함께 "라이브 데모"로 심사위원에게 보여줄 프론트엔드 구성안.
> 기존 `web/` (Next.js + ReactFlow + Tailwind)에 섹션을 추가/재배치해 내러티브를 영상과 일치시키는 게 목표.

---

## 0. 설계 원칙

| # | 원칙 | 이유 |
|---|---|---|
| 1 | **Findings-first, model-second** | 심사위원은 "무엇을 발견했나"를 가장 먼저 본다. 시스템 설명은 그 다음. |
| 2 | **모든 카드에 비교 수치** | "PR-AUC 0.265"보다 "**무작위의 10.6배**"가 임팩트. 절대값 단독 금지. |
| 3 | **v3/v4 같은 내부 코드명 금지** | UI 문구는 무조건 기능명("15-stage funnel", "calibrated ensemble", "결제 후 위험"). |
| 4 | **라이브 데이터 표시** | 모든 숫자는 `zerve.variable()` → FastAPI 라이브 fetch. 정적 JSON 금지(폴백 제외). |
| 5 | **인터랙션 = 즉시 반응 (<300ms)** | 클릭/입력 후 0.3초 안에 시각적 피드백. 로딩 스피너는 cancel 가능하게. |
| 6 | **다크 + 핑크/시안 그라디언트** | 기존 `Hero` shader 톤 유지. 일관성. |
| 7 | **Above-the-fold = 한 줄 결론** | 첫 화면에 "350만 이벤트로 만든 모델은 무작위의 10.6배 정확합니다" 같은 한 문장. |

## 1. 섹션 구조 (위→아래 11개 섹션)

```
┌────────────────────────────────────────────────────┐
│  HERO          한 줄 결론 + 핵심 4숫자             │
├────────────────────────────────────────────────────┤
│  01 · 발견     사용자 행동의 3가지 진실 (카드 3개) │
├────────────────────────────────────────────────────┤
│  02 · 퍼널     15단계 sankey + post-upg 도넛       │
├────────────────────────────────────────────────────┤
│  03 · 전이     transition heatmap + 핵심 경로 강조 │
├────────────────────────────────────────────────────┤
│  04 · 시그널   3-flag combo 인터랙티브 토글        │
├────────────────────────────────────────────────────┤
│  05 · Leakage  audit 21/21 + obs_days 발견 일화    │
├────────────────────────────────────────────────────┤
│  06 · 모델     5개 모델 head-to-head + PR 곡선     │
├────────────────────────────────────────────────────┤
│  07 · 시뮬레이터 Top-K 슬라이더 (캠페인 ROI 계산)  │
├────────────────────────────────────────────────────┤
│  08 · 라이브   row index → 예측 확률              │
├────────────────────────────────────────────────────┤
│  09 · 액션     7-action playbook                   │
├────────────────────────────────────────────────────┤
│  10 · 전략 AI  K2 segment-pick → 3 ranked actions  │
├────────────────────────────────────────────────────┤
│  11 · 캔버스   ReactFlow DAG (현 위치, 시스템 증명) │
├────────────────────────────────────────────────────┤
│  END           Insights Card + 링크                │
└────────────────────────────────────────────────────┘
```

기존 `web/`은 4섹션(Canvas → LivePredict → Strategy → Insights). **이 안은 11섹션으로 확장**하되 신규 섹션은 단순한 grid + 차트라 구현 부담 적음.

## 04 · 시그널 인터랙티브 — "3-flag 조합 토글"

**목적**: 영상 1:23. 행동 시그널 3개 ON/OFF로 결제율이 어떻게 변하는지 직접 토글.

```

│   [ ] 온보딩 완주자                                 │
│                                                      │
│   ┌──────────────────────────────────┐              │
│   │  해당 사용자 수 :   9,324명     │              │
```

```
│              0%   1%   5%  10%  20%  50%  100%            │

│   ┌──────────────┬──────────────┬──────────────┐          │
│   │ 타겟 인원    │ 결제자 포착  │ 적중률        │          │
```

| 비용 가정 | 사용자가 LTV/이메일 단가 직접 조정 가능 |

## 5. 시연 시나리오 (3분 영상에 맞춤)

심사위원이 영상 본 뒤 라이브 사이트 클릭하면:

1. **Hero**에서 punchline 한 줄 → 이미 영상에서 들은 숫자라 즉시 이해
2. **01 발견**의 3 카드를 순서대로 hover (각 lift 추가 reveal)
3. **02 퍼널**의 sankey에서 `8.Upgraded` 클릭 → 결제 후 위험 토스트
4. **04 토글** 3개 모두 ON → "55× spread" 토스트
5. **05 leakage** "obs_days alone ROC 0.939" 일화 카드
6. **07 시뮬레이터** 슬라이더를 1% → 5% → 10% 이동, 결제자 포착 수 변화 watch
7. **08 predict** "결제자 한 명 보기" 클릭 → SHAP feature 펼침
8. **10 K2** segment 클릭 → 3 액션 카드
9. **11 canvas** scroll 도달 → DAG로 "이 모든 게 한 캔버스" 증명

이 9-step을 약 60초에 클릭으로 보여주면 영상+사이트 = 4분 만에 모든 루브릭 항목이 dual-checked.
